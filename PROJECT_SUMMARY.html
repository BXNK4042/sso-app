1. ภาพรวมโครงการ (Project Overview)

โปรเจกต์นี้เป็นการออกแบบและพัฒนาระบบ Single Sign-On (SSO) ส่วนกลาง สำหรับองค์กรหรือสถานศึกษา (เช่น KMITL) โดยมีแนวคิดหลักคือ:

  • เข้าสู่ระบบเพียงครั้งเดียว (Single Sign-On): เมื่อผู้ใช้งานล็อกอินผ่านบริการ Central Authentication แล้ว จะได้รับคุกกี้ JWT บัตรผ่านสิทธิ์ ทำให้สามารถเปิดใช้งานระบบอื่นๆ ในเครือข่ายได้ทันทีโดยไม่ต้องล็อกอินซ้ำ
  • FreeRADIUS เป็นศูนย์กลางการยืนยันตัวตน (Authentication Engine): ใช้วิธีมาตรฐาน UDP RADIUS (Port 1812) ตรวจสอบความถูกต้องของบัญชีผู้ใช้
  • PostgreSQL จัดเก็บข้อมูลผู้ใช้อย่างง่ายแต่ทรงพลัง: เดิมทีมีแผนใช้ OpenLDAP แต่ทีมได้ปรับปรุง (Refactor) มาใช้ PostgreSQL Table users เดียว พร้อมใช้ extension pgcrypto รองรับทั้งรหัสผ่านธรรมดา (Plaintext) และรหัสผ่านที่เข้ารหัสแบบ Bcrypt
  • Microservices เต็มรูปแบบผ่าน Docker Compose: มีบริการทั้งหมด 7 ตัวทำงานร่วมกันในเครือข่าย Docker sso-network ประกอบด้วย Nginx Reverse Proxy, Central Auth, Web App 1 (Lab Booking), Web App 2 (IT Equipment Loan), FreeRADIUS, PostgreSQL และ pgAdmin 4
💡
สถานะปัจจุบัน: ตัวโค้ดทั้งหมดได้ถูกดึง (fetch & pull/merge) รวมเข้าสู่เครื่องเรียบร้อยแล้ว ทุกฟังก์ชันจากทุก branch ของเพื่อนร่วมทีม (bank, first, leo, riew, fah) ได้ถูกผสานเข้ากับกิ่ง main และนำมาอัปเดตลงใน workspace นี้อย่างครบถ้วน

4. ลำดับขั้นตอนการทำงานของ SSO (Authentication Step-by-Step)

1
ผู้ใช้เปิดหน้าเว็บระบบย่อย (เช่น /lab/booking หรือ /equipment/borrow)
แอปพลิเคชัน (FastAPI) จะดึงคุกกี้ชื่อ sso_token หรือ Bearer Header มาตรวจสอบ หากไม่มีหรือ Token หมดอายุ จะทำ HTTP 303 Redirect ผู้ใช้ไปยัง http://localhost:9999/auth/login?redirect=/lab/booking
2
Central Auth แสดงหน้าจอ Login และรับข้อมูลบัญชี
ผู้ใช้กรอก Username และ Password ในแบบฟอร์ม หน้าเว็บส่งแบบฟอร์ม POST /auth/login พร้อมพารามิเตอร์ซ่อน redirect_url
3
ส่งแพ็กเก็ต RADIUS Access-Request ผ่าน UDP
FastAPI เรียกใช้ฟังก์ชัน authenticate_with_radius() ส่งแพ็กเก็ต UDP พอร์ต 1812 ไปยังโฮสต์ sso-radius โดยมีการเข้ารหัสลับด้วย Shared Secret sso_secret_123 และแนบ Message Authenticator
4
FreeRADIUS คิวรีตรวจสอบรหัสผ่านใน PostgreSQL
FreeRADIUS รัน Authorize Query ในโมดูล SQL: 
SELECT id, username, 
       CASE WHEN password LIKE '$%' THEN 'Crypt-Password' ELSE 'Cleartext-Password' END AS attribute, 
       password AS value, ':=' AS op 
FROM users WHERE username = '%{SQL-User-Name}';
ระบบจะตรวจสอบว่าหากรหัสขึ้นต้นด้วยเครื่องหมาย $ (เช่น $2a$ หรือ $2b$ ของ Bcrypt) จะเทียบด้วยระบบ Crypt อัตโนมัติ แต่ถ้าไม่ขึ้นต้นด้วย $ จะถือว่าเป็น Plaintext ทำให้รองรับทั้งสองแบบได้อย่างชาญฉลาด
5
FreeRADIUS ส่งผลลัพธ์ตอบกลับ (Access-Accept / Access-Reject)
ถ้ารหัสผ่านถูกต้อง FreeRADIUS จะส่งแพ็กเก็ต Access-Accept กลับมา ถ้าผิดหรือไม่พบบัญชีจะส่ง Access-Reject
6
ออกบัตรผ่าน JWT Token และบันทึกลงในคุกกี้
เมื่อผ่านการตรวจสอบ Central Auth จะตรวจสอบ Role ของผู้ใช้ (หากเป็น admin หรือ teacher01 จะได้สิทธิ์ admin นอกนั้นเป็น student) จากนั้น Sign JWT Token ด้วย JWT_SECRET (อายุ 2 ชั่วโมง) แล้วเขียนลงในคุกกี้ sso_token พร้อมตั้งค่า HttpOnly=True, Path="/", SameSite="lax"
7
Redirect กลับสู่ระบบต้นทางอย่างราบรื่น (Single Sign-On Experience)
เบราว์เซอร์ถูกส่งกลับไปยัง redirect_url (เช่น /lab/booking) โดยคราวนี้เบราว์เซอร์ได้แนบคุกกี้ sso_token ไปด้วย ทำให้ Web App 1 ถอดรหัสอ่านสิทธิ์ได้ทันที และหากผู้ใช้เปิดแท็บใหม่ไปยัง Web App 2 (/equipment/borrow) เบราว์เซอร์ก็จะแนบคุกกี้เดิมไปด้วยทันทีโดยไม่ต้องกรอกรหัสผ่านใหม่อีก!
8
การออกจากระบบส่วนกลาง (Central Logout)
เมื่อคลิกปุ่ม Logout ในแอปใดก็ตาม ระบบจะพาไปยัง /auth/logout ซึ่งจะทำการสั่งเบราว์เซอร์ให้ลบคุกกี้ sso_token ที่ Path=/ ส่งผลให้สิทธิ์การเข้าใช้งานหลุดออกจากทุกแอปพลิเคชันพร้อมกันทันที

6. โครงสร้างฐานข้อมูล (Database Schemas)

6.1 ฐานข้อมูลกลางผู้ใช้ (PostgreSQL: radius)

สร้างขึ้นจากไฟล์ database/init.sql ประกอบด้วย 1 ตารางหลักที่กระชับแต่ครบถ้วน:

SQL Schema: database/init.sql 
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE IF NOT EXISTS users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(64) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'student',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT users_role_check CHECK (role IN ('admin', 'student'))
);

6.2 ฐานข้อมูลเฉพาะแอปพลิเคชัน (SQLite Databases)

ทั้ง 2 แอปพลิเคชันแยกเก็บฐานข้อมูลแบบ SQLite ในโฟลเดอร์ database/ เพื่อความเป็นอิสระของข้อมูลทางธุรกิจ (Data Isolation):

แอปพลิเคชัน ตำแหน่งไฟล์ ตาราง (Table) คอลัมน์และโครงสร้างข้อมูล
Web App 1 (Lab) database/web-app-1.db lab_computers id (PK), room, status (available/booked), booked_by, time
Web App 2 (Equipment) database/web-app-2.db equipments id (PK), name, category, status (available/borrowed), borrowed_by, due_date

8. วิธีการรันและทดสอบระบบ (Setup & Testing Guide)

8.1 การเริ่มระบบด้วย Docker Compose

รันคำสั่งจากรากของโปรเจกต์นี้:

Terminal Bash 
# สร้างและเริ่มคอนเทนเนอร์ทั้งหมด 7 ตัวใน background
docker-compose up -d --build

# ตรวจสอบสถานะการทำงานของคอนเทนเนอร์
docker-compose ps

8.2 การทดสอบ FreeRADIUS ผ่าน Command-Line ด้วย radtest

สามารถทดสอบได้ทันทีโดยไม่ต้องเปิดเบราว์เซอร์:

Terminal Bash 
# 1. ทดสอบผู้ใช้รหัสผ่านธรรมดา (john)
docker exec -it sso-radius radtest john password123 127.0.0.1 0 sso_secret_123

# ผลลัพธ์ที่ถูกต้อง:
# Received Access-Accept Id ... from 127.0.0.1:1812

# 2. ทดสอบผู้ใช้รหัสผ่าน Bcrypt (alice)
docker exec -it sso-radius radtest alice alicepassword123 127.0.0.1 0 sso_secret_123

# 3. ทดสอบรหัสผ่านผิด (ต้องถูก Reject)
docker exec -it sso-radius radtest john wrongpassword 127.0.0.1 0 sso_secret_123

# ผลลัพธ์:
# Received Access-Reject Id ...

10. จุดเด่นด้านความปลอดภัยและการปรับปรุงโค้ด (Refactoring Highlights)

🔐 Dynamic Password Detection
FreeRADIUS ใช้ SQL query ดักจับอักขระตัวแรกของรหัสผ่าน: หากขึ้นต้นด้วย $ จะสลับไปใช้ Crypt-Password สำหรับ Bcrypt Hashing ทันที และหากเป็นข้อความปกติจะใช้ Cleartext-Password ทำให้มีความยืดหยุ่นสูง
🍪 HttpOnly & SameSite Cookie
JWT Token จัดเก็บในคุกกี้ sso_token แบบ HttpOnly=True ป้องกันการโจมตีประเภท Cross-Site Scripting (XSS) ขโมย Token ผ่าน JavaScript และตั้งค่า SameSite="lax" ป้องกัน CSRF
⚡ Single-Origin Reverse Proxy
Nginx รวมบริการทั้งหมดให้อยู่บน Port 9999 ภายใต้โดเมนเดียวกัน ทำให้ไม่มีปัญหาเรื่อง Third-party Cookie Blocking ในเบราว์เซอร์ยุคใหม่ (Chrome, Safari, Firefox)
🧹 Clean Code & Guard Clauses
โค้ดใน web-app-1 และ web-app-2 ได้รับการ Refactor ลบ dead code, แยก Database Helper ชัดเจน, เปลี่ยน Magic Strings เป็น Constants, และใช้ Early Return Guard Clauses เพื่อความปลอดภัย
